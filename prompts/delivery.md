# 실제 증거로 산출물 작성

이 프롬프트는 산출물 작성 단계에서 사용한다. 운영·승인·시간·검증 규칙은 [AGENTS.md](../AGENTS.md)를 따른다. 최초 경로 연결은 [setup.md](setup.md)의 책임이며 여기서 과제 환경을 재설정하지 않는다.

새 세션이라면 setup의 재개 순서로 기존 기록과 승인 상태를 먼저 확인하고 이어간다. 각 산출물 작업 시작·종료와 검증 후 경과·남은 시간을 확인해 최종 검증·제출 여유를 확보한다. 긴 작업은 착수 전에 완료 기준·시간 상한을 계획에 기록한다. 원래 시작·마감 시각을 유지하고 시간 예산을 초기화하지 않는다. 시간 확인이 안 되면 현재 남은 시간만 사용자에게 확인해 progress에 기록한다. 135분 이후 새 확장 금지는 운영 규칙이며 자동 타이머에 의한 강제 중단을 뜻하지 않는다.

## 입력과 확인

1. 확인된 TASK_ROOT에서 과제의 최신 요구 산출물·제출 형식·경로·마감·제출 방법·시험 규정을 읽는다. 이전에 확인한 내용과 달라졌으면 변경과 영향을 알린다. 필수 자료가 없거나 충돌이 해결되지 않았다면 해당 산출물·제출을 임의로 가정하지 않는다.
2. 실제 코드와 기존 과제 문서, 승인된 implementation-plan, findings, progress를 읽는다. 기본 경로는 AGENTS.md의 작업 문서 표를 따르되 setup에서 재사용하기로 매핑한 문서가 우선이다. 계획은 구현 증거가 아니며, 진행 기록과 코드가 다르면 실제 상태를 확인해 구분한다.
3. 요구 산출물별로 필요한 근거를 연결한다. 테스트 기록의 검사 대상·시각·명령·기대/실제 결과를 확인한다. 코드가 마지막 검사 이후 바뀌었다면 영향을 확인하고 필요한 재검증을 수행하거나 미검증으로 표시한다.

## 작성 절차

| 산출물에 반영할 내용 | 근거 | 작성 규칙 |
| --- | --- | --- |
| 문제 정의·대상·성공 기준 | 과제 명세, 승인 계획, findings | 승인된 방향과 평가 기준을 설명 |
| 선택 이유·제외 범위 | 승인된 대안 비교와 결정 기록 | 사용자 결정과 에이전트 판단을 구분 |
| 실제 구현 내용 | 코드·변경 파일·실행 상태 | 계획만 있고 없는 기능을 구현했다고 쓰지 않음 |
| 실행 방법 | 과제의 실제 환경·설정·확인한 실행 명령 | 작업 디렉터리·필수 설정을 설명. 실행하지 않았다면 미실행 표시. 비밀값은 넣지 않음 |
| 검증 결과 | progress의 명령/시나리오·기대/실제 결과·검사 범위 | 통과·실패·미검증을 구분. 없는 성능·수치·테스트 결과를 만들지 않음 |
| 한계·다음 단계 | 미구현·실패·미검증·보류 기록 | 제출 시점의 제약을 명시하고 제안을 완료 기능처럼 쓰지 않음 |

과제가 요구하는 문서·발표·데모 설명·파일 형식에 맞춰 위 내용을 배치한다. 과제에서 요구하지 않는 산출물을 관성적으로 추가하지 않는다. 기존 README와 산출물은 먼저 읽고 필요한 부분만 보완하며 덮어쓰지 않는다. 새 파일 경로가 기존 파일과 충돌하면 내용을 확인하고 안전한 보완 방법을 결정한다.

작성 중 제품 변경이 필요하면 개발자→검증자로 돌아가 변경과 검사 결과를 progress에 남긴다. 승인 범위를 바꾸면 재승인받는다. 135분 이후 새 확장을 시작하지 않는다.

## 제출 전 확인

- 요구 산출물의 존재·경로·형식·파일명, 링크 대상과 접근 가능 여부를 확인한다. 접근을 검사하지 못한 링크는 미확인으로 표시한다.
- 최종 smoke test는 핵심 사용자 흐름을 대상으로 실제 수행한다. 전체 테스트와 동일하다고 표현하지 않는다. 실행 불가·실패·미검증과 남은 위험을 기록한다.
- 구현 완료·검증 통과·산출물 준비·제출 완료를 구분한다. 문서를 읽거나 문서 링크를 확인한 것은 실행 테스트 통과의 근거가 아니다.
- 최종 제출 조작은 시험 안내와 사용자의 승인 범위에 따른다. 대상·내용·행위가 이미 명시적으로 승인되어 있으면 반복 확인하지 않는다. 없으면 검토 가능한 제출 묶음과 필요한 조작을 제시하고 승인받는다. 도구 권한도 별도로 준수한다.
- 실제 제출 후 결과 화면·접수 상태·제출 시각 등 확인 가능한 증거만 기록한다. 조작할 수 없거나 결과를 확인할 수 없으면 제출 준비 또는 결과 미확인으로 보고한다. 준비만 끝난 상태를 제출 완료라고 쓰지 않는다.

## 출력

과제 지정 산출물과 짧은 인계 보고를 제공한다. 보고에는 생성·수정 경로, 실제 검증 결과, 실패·미검증·한계, 제출 상태와 다음 필요한 행동을 담는다. 추정이나 자기 검토를 측정 결과·독립 검토라고 쓰지 않는다.
