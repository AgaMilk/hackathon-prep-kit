# 180분 해커톤 준비자료

공개 원문에서 선별한 운영 지침으로 문제 정의부터 구현·검증·산출물·제출까지 진행하는 준비자료다. Superpowers는 진행·디버깅·검증, Ponytail은 단순한 구현 원칙, Planning은 findings/progress 양식에 활용한다. 전체 원본 Skill 설치본이 아니며 원문과 다른 절차는 **해커톤용 조정**으로 구분한다.

## 문서 역할

| 문서 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 반복 적용할 역할·묶음 승인·180분 진행·검증·기록 규칙 |
| [prompts/setup.md](prompts/setup.md) | 최초 한 번 두 루트·과제 지침·참조 자료·작업 문서를 연결 |
| [prompts/delivery.md](prompts/delivery.md) | 실제 구현·검증 증거로 과제 요구 산출물을 작성 |
| [SOURCES.md](SOURCES.md) | 원문 출처·고정 커밋·라이선스·확보 결과와 실패 이력 |
| `references/` | 수정하지 않는 원본 스냅샷과 템플릿. 필요한 문서만 단계별로 읽음 |

## 시작과 사용 순서

1. 실제 공개 준비자료 저장소가 제공되면 내려받아 로컬에서 연다. 공개 주소는 https://github.com/AgaMilk/hackathon-prep-kit 이다. `SOURCES.md`와 `references`가 포함되어 있는지 확인한다. **다운로드는 Skill 활성화가 아니다.** 자동 설치·훅·모드 전환은 필요하지 않다.
2. 실제 과제 프로젝트를 준비한 뒤 Codex에 아래처럼 요청한다. 꺾쇠 부분은 본인이 확인한 경로로 바꾼다. KIT_ROOT와 TASK_ROOT의 위치 관계는 가정하지 않는다.

   > KIT_ROOT는 `<준비자료 경로>`, TASK_ROOT는 `<실제 과제 경로>`다. KIT_ROOT/prompts/setup.md를 읽고 최초 연결 절차를 수행해 줘. 과제의 기존 지침을 우선하고, 필요한 참조만 읽어 줘. 구현 전에 문제·아이디어·범위·설계·검증 기준·구현 계획을 한 묶음으로 승인받아 줘.

3. 연결 결과와 짧게 묶인 질문을 확인하고, 핵심 범위·제외 범위·허용 확장 후보까지 검토해 승인한다. 실제 과제가 지정되지 않았다면 과제 작업 문서를 만들지 않는다. 준비자료 AGENTS.md가 과제에 자동 적용된다고 가정하지 않는다.
4. 승인 범위 안에서는 에이전트가 분석자→계획자→개발자→검증자→문서 작성자로 전환하며 진행한다. 핵심 검증 후 확장하고 매 확장마다 회귀검증한다. 방향의 실질적 변경만 재승인한다. 도구 권한과 시험 규정은 별도로 따른다.
5. 135분부터 산출물 작성에 집중한다. 다음처럼 요청하거나 이미 승인된 진행 흐름에서 delivery 절차로 전환한다.

   > KIT_ROOT/prompts/delivery.md에 따라 실제 코드·계획·findings·progress의 증거로 과제 요구 산출물을 작성해 줘. 실패·미검증·한계를 구분하고 최종 검증과 제출 상태를 알려줘.

6. 165–180분에는 최종 smoke test와 제출 확인을 수행한다. 제출 조작은 시험 안내와 승인 범위에 따른다. 구현 완료·검증 통과·제출 완료는 별개다.

TASK_ROOT의 기존 문서를 우선 재사용한다. 없으면 `docs/hackathon/implementation-plan.md`, `docs/hackathon/findings.md`, `docs/hackathon/progress.md`를 필요한 시점에 만든다. 별도 task_plan.md는 만들지 않고, 작업용 progress의 참조를 implementation-plan으로 연결한다. 원본 템플릿과 과제의 기존 AGENTS.md·README를 덮어쓰지 않는다.

중단·재개 정보는 TASK_ROOT의 progress에 남긴다. 개인 PC의 실제 경로는 공개 키트 문서에 넣지 않는다. 새 세션에서는 다음처럼 요청한다.

> TASK_ROOT는 `<실제 과제 경로>`다. 과제의 기존 지침 → progress → 기록된 KIT_ROOT/AGENTS.md → 현재 단계의 계획·findings·필요한 참고 문서 순서로 확인하고 다음 행동부터 재개해 줘. 끝난 setup과 승인된 계획은 반복하지 말고, 원래 시작·마감 시각과 승인 상태를 유지해 시간 예산을 초기화하지 마.

각 작업 시작·종료와 검증 후 시간을 확인해 남은 검증·산출물·제출 여유로 다음 작업을 정한다. 긴 작업은 완료 기준·시간 상한을 계획에 넣는다. 135분 이후 새 확장은 시작하지 않으며, 이는 자동 타이머 기능이 아닌 운영 규칙이다. 시간 확인이 안 되면 현재 남은 시간만 사용자에게 확인해 기록한다.

준비자료 연결은 5분 목표이며 실측 성과가 아니다. 모델을 확인·선택할 수 있다면 제공되는 6.1 Sol medium을 권장하고, 없으면 제공 모델·기본값을 사용한다. 모델이나 설정을 추정하지 않으며 업데이트·API 키·로그인을 요구하지 않는다. 설치·실행·호환성 검증이나 Skill 활성화 완료를 자료 확보·문서 점검만으로 주장하지 않는다.
